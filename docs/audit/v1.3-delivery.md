## 2. Diffs de schema

### 2.1 `prisma/schemas/core.prisma`

Mudanças:

- **`User`** virou identidade GLOBAL:
  - removidos `tenantId` e FK para `Tenant`
  - adicionados `locale`, `timezone`
  - relações: `memberships`, `authAccounts`, `appSessions`
- **`Tenant.users[]`** removido (não existe mais relação direta).
- **`Membership`** ganhou `invitedAt` e `lastActiveAt`.
- **Novo `AuthAccount`**: `(provider, providerSubject)` é único; permite
  identity linking automático por email normalizado.
- **Novo enum `AuthProvider`**: `MAGIC_LINK`, `OTP`, `OAUTH_GOOGLE`,
  `OAUTH_GITHUB`, `PASSWORD`.
- **Novo `AuthVerificationChallenge`**: persiste OTP/magic-link com
  `codeHash` (bcrypt), `attempts`/`maxAttempts`, `expiresAt`, `consumedAt`.
  Substitui o `Map<token, ...>` em memória das strategies V1.1.
- **Novo enum `AuthChallengeKind`**: `OTP`, `MAGIC_LINK`.
- **Novo `AppSession`** (substitui `SharedSession`):
  `tokenHash @unique` (SHA-256), `issuedAt`, `expiresAt`, `revokedAt`,
  `lastSeenAt`, `ipHash`, `userAgent`. Uma sessão por app — a "sessão
  cross-app" é derivada por `User.appSessions.filter(active)`.
- **`TelemetryRecord.category`** adicionado (string
  `InstitutionalTelemetryCategory`); índices novos em `(tenantId, category)`
  e `(occurredAt, category)`.

Lei L5 preservada: user global + apps multi-tenant via `Membership`.
Lei L3 preservada: zero cross-schema FK.

### 2.2 `prisma/schemas/hub.prisma` (novo)

5 modelos JSON-first (para evitar hiper-normalização prematura §6.3):

- **`InstitutionalProject`** — uma linha por projeto.
  Colunas tipadas para consultas: `name`, `slug`, `status`, `visibility`,
  `ownerTenantId?`, `lastIngestedAt?`, `lastHealthStatus?`.
  Campos JSON (snapshots vivos do último ingestion):
  `manifestSnapshot`, `publicMetricsSnapshot`, `healthSummarySnapshot`,
  `readinessSummarySnapshot`, `brandSnapshot`, `mcpSnapshot`,
  `integrationSnapshot`.
- **`InstitutionalSource`** — `(sourceId, sourceType)` único; guarda
  `trustLevel` e `ingestMode`.
- **`InstitutionalIngestionRun`** — 1 linha por run. Contadores
  (`acceptedCount`, `rejectedCount`, `skippedCount`, `durationMs`) +
  JSON (`rejections`, `warnings`, `summary`).
- **`ProjectHealthSnapshot`** — série temporal de health (`overallStatus`,
  `components` JSON).
- **`ProjectPublicMetricsSnapshot`** — série temporal de métricas
  (`metrics` JSON tipado pelo DTO).

Scripts adicionados em `package.json`:

- `prisma:validate:hub`, `prisma:generate` (+ 4 por app), `demo:flows`.

**Princípios aplicados:**

- **Factory functions** `makeXRepo(client)` — sem singleton, fácil de injetar
  em testes (L11: explicit DI).

- **Sub-paths por app** (`@matriz/platform-db/core`,
  `@matriz/platform-db/core/repositories`, etc.) — um app só importa o que
  precisa, preservando L3 (sem tipos vazando entre schemas).

Paths registrados em `tsconfig.base.json` (9 aliases novos).

## 4. Auth real cross-app

Módulo novo: `packages/platform/auth/src/v1/server/` (importável via
`@matriz/platform-auth/server-db`).

### 4.1 Primitivas expostas

| Função | Persistência | Descrição |
|---|---|---|
| `issueOtpChallenge(email, meta?)` | `AuthVerificationChallenge` | Gera OTP 6 dígitos, hash bcrypt, TTL 10min |
| `issueMagicLinkChallenge(email, meta?)` | `AuthVerificationChallenge` | Gera token 32-byte, hash SHA-256, TTL 15min |
| `verifyChallenge(kind, email, code)` | consume + incrementa `attempts` | Verdict tipado: `ok` / `expired` / `exhausted` / `invalid` |
| `resolveIdentityByEmail({email, provider, displayName?})` | `User` + `AuthAccount` | **Identity linking automático**: se email já existe, faz attach de novo `AuthAccount`; senão cria `User` novo |
| `issueSession({identity, tenantId, appId, strategyId})` | `AppSession` | Retorna `{ session, rawToken }` — só o hash vai pro DB |
| `readSessionByToken(rawToken)` | — | Lê por `tokenHash`, valida expiry/revoke, atualiza `lastSeenAt` |
| `revokeSessionByToken(rawToken)` | — | Marca `revokedAt` |
| `revokeAllSessionsForUser(userId)` | — | Revoga todas sessões ativas |

### 4.2 Decisões tomadas (§11 do plano)

1. ✅ Client Prisma por app (via wrappers; zero singleton compartilhado).
2. ✅ 1 Postgres físico + N schemas lógicos via `?schema=<app>` em `.env`.
3. ✅ Providers reais: OTP + MAGIC_LINK. OAuth/password só declarados no enum.
4. ✅ Identity linking automático por email normalizado, sem confirmação.

### 4.3 O contrato público do pacote `auth` NÃO mudou

- `AuthSession`, `AuthIdentity`, `AuthSessionService` (client-side) intactos.
- Strategies V1.1 (`createMagicLinkStrategy`, `createOtpStrategy`)
  continuam funcionando para o modo fake/in-memory.
- Apps que já usam o protocolo não quebram. As novas primitivas são
  opt-in em server routes.

## 5. MCP real no Hub

### 5.1 Protocolo

JSON-RPC 2.0 direto (sem SDK), endpoint: `POST /api/mcp`.

Métodos suportados:

| Método | Retorna |
|---|---|
| `initialize` | protocolVersion, serverInfo, capabilities declaradas |
| `ping` | `{}` |
| `resources/list` | 1 resource template + lista de resources concretos (1 por projeto) |
| `resources/read` | bundle do projeto (manifest + health + metrics + brand + mcp + integrations + ingestion) |
| `tools/list` | 1 tool com inputSchema JSON Schema |
| `tools/call` | result + structuredContent + isError |

### 5.2 Resource real: `matriz://projects/{projectId}`

Retorna, ao fazer `resources/read`:

\`\`\`json
{
  "projectId": "...",
  "manifest": ProjectManifest,
  "publicMetrics": ProjectPublicMetricsDTO,
  "healthSummary": HealthSummaryDTO,
  "readinessSummary": ReadinessSummaryDTO,
  "brand": ProjectBrandIdentityDTO,
  "mcp": ProjectMcpCapabilitiesDTO,
  "integrations": ProjectIntegrationCapabilitiesDTO,
  "ingestion": { "sourceType", "trustLevel", "ingestMode", "lastIngestedAt", "lastRunStatus" },
  "snapshotTakenAt": ISODateTime
}
\`\`\`

Implementação: `apps/matriz-hub/src/mcp/resources.ts`.
Fonte: lê do `InstitutionalRegistry` em memória (preenchido pelo
`runInstitutionalIngestion()`). Quando o DB está disponível, a persistência
em `InstitutionalProject` é feita por `persistIngestionRun`.

### 5.3 Tool real: `refresh_project_ingestion`

Schema de entrada:

\`\`\`json
{
  "properties": {
    "projectId": { "type": "string" },
    "persist":   { "type": "boolean", "default": true }
  },
  "required": ["projectId"]
}
\`\`\`

O que a tool faz:

1. Roda `runInstitutionalIngestion()` real (o mesmo que o bootstrap).
2. Se `persist: true` e Hub DB disponível → chama `persistIngestionRun`
   (upsert de `InstitutionalProject` + `InstitutionalSource` + insert
   de `InstitutionalIngestionRun` + snapshots).
3. Retorna `{ run: { durationMs, accepted, rejected, skipped, reason }, projectFound, persisted }`.

Implementação: `apps/matriz-hub/src/mcp/tools.ts`.

### 5.4 Endpoint HTTP

`apps/matriz-hub/app/api/mcp/route.ts`:

- `POST` aceita request único OU batch (array).
- Valida JSON-RPC envelope (`jsonrpc === "2.0"`, `method`).
- Mapeia erros internos para códigos JSON-RPC:
  -32600 (invalid request), -32601 (method not found),
  -32602 (invalid params), -32603 (internal error),
  -32700 (parse error).
- `GET` retorna metadata de discovery (útil para debug).

### 6.2 Demo script (`scripts/demo-flows.ts`)

Executa os 4 fluxos end-to-end contra Postgres real quando configurado:

| Fluxo | Prova |
|---|---|
| **A — Primeiro login** | issueOtpChallenge → verify → resolveIdentityByEmail cria `User` + `AuthAccount` + ensure `Membership` → issueSession → readSessionByToken retorna sessão |
| **B — Login cross-app** | mesmo email, provider `MAGIC_LINK` → resolveIdentityByEmail encontra `User` existente e cria novo `AuthAccount` attached (identity linking automático, `linkedUserId === originalUserId`) |
| **C — Ingestion persistida** | `runInstitutionalIngestion()` + `persistIngestionRun()` → counts de `institutionalProject` / `institutionalIngestionRun` / `institutionalSource` > 0 |
| **D — Contract persistido com ExternalLink** | Seumei `establishment` criado → Contracts `contract` + party + version + event criados em 1 transaction → `ExternalLink` em core `contracts → seumei` → `TelemetryRecord` com `category: "governance"` → links legíveis nos dois sentidos |

Rodar:

\`\`\`bash
# 1. Configure DATABASE_URL em .env
# 2. Aplique schemas (dev only; em prod será migration):
pnpm exec prisma db push --schema prisma/schemas/core.prisma
pnpm exec prisma db push --schema prisma/schemas/hub.prisma
pnpm exec prisma db push --schema prisma/schemas/seumei.prisma
pnpm exec prisma db push --schema prisma/schemas/contracts.prisma
# 3. Rode os fluxos:
