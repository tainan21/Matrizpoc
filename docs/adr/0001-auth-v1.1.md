# ADR 0001 — Auth V1.1: shared core + per-app adoption

- **Status**: Accepted
- **Date**: 2026-04-22
- **Supersedes**: prior mock-only `packages/platform/auth`

## Context

V1 left `packages/platform/auth` as a bag of type aliases. No provider,
no hooks, no strategies, no storage adapter. Each app had to reinvent
sign-in locally, which is both a risk for duplication and an obstacle
to validating the shared-auth theorem from the charter.

## Decision

Build `platform-auth` as a **motor**, not a UI kit. Every app adopts it
locally under `apps/<app>/src/auth/` and renders its own login screen
under `apps/<app>/src/domains/login/presentation/`.

### Surface (stable, versioned under `/v1`)

- Types: `AuthUser`, `AuthSession`, `AuthIdentity`, `AuthTenantAccess`,
  `AuthStatus`, `AuthError`.
- Zod schemas mirroring each type.
- `SignInStrategy` contract with two reference implementations:
  `createOtpStrategy()` and `createMagicLinkStrategy()`.
- `SessionStorage` contract + `createSessionStorage(appId)` factory backed
  by `@matriz/platform-storage`.
- `AuthProvider` + `useAuth`, `useSession`, `useAuthStatus`.
- `AuthGate` (client) + `requireSession` (server/edge helper).
- Services: `createSession`, `restoreSession`, `refreshSession`, `signOut`.

### Per-app adoption (template)

```
apps/<app>/src/auth/
  config.ts          default strategy, copy, branding tokens
  strategies.ts      list of enabled strategies
  provider.tsx       composes AuthProvider with config
  guards.ts          wraps AuthGate + tenant checks
  session.mapper.ts  AuthSession → app view model
  use-auth-tenant.ts composes useAuth + useTenant
```

### Strategy choices (proof of flexibility)

- matriz-hub → magic link
- spot → OTP
- seumei → OTP
- contracts → magic link
- willdash → magic link

## Consequences

**Positive**

- Auth lives in one package, UI stays per app — identity visual of each
  app is preserved (`appThemes.<app>` in `design/system`).
- Strategy is a plugin: adding SSO or password later is a new file, not a
  rewrite.
- Storage is an adapter: moving from `localStorage` to HTTP-only cookies
  is a one-file swap.
- Sessions are namespaced by `appId`, so subdomains do not cross-read.

**Negative / accepted trade-offs**

- No SSO across subdomains in V1.1. Planned V2 work: cookie adapter +
  shared eTLD+1 session.
- OTP codes and magic link tokens are in-memory in the POC; a real
  backend replaces those maps without changing the provider surface.

## Why not put login UI in the package?

Because identity is owned by each app. `spot` must look like Spot on
login; `contracts` must feel like a ledger; Hub must feel institutional.
If the package shipped a UI, we'd be enforcing one brand and creating a
bottleneck for five product teams. The package ships **behavior**, the
app ships **pixels**.
